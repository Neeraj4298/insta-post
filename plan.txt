# Viral Reel Creator — Complete Practical Development Blueprint

Below is the plan I recommend you actually build.

I am deliberately **not** designing this as a SaaS, microservice architecture, or "Opus Clip clone." With an **i5 + 8 GB RAM + ₹0 budget**, that would be stupid engineering.

The product should first be a **local AI-powered reel extraction tool**.

# 1. Product Definition

## Working name

**ClipForge Local**

You can rename it later.

## One-line product vision

> Paste a long-form video link, analyze the content locally using free AI, identify the strongest standalone short-form moments, and generate vertical captioned reels.

## Core target use case

The first version should focus on:

* Sermons
* Christian podcasts
* Testimonies
* Interviews
* Educational videos
* Podcasts
* Long talking-head videos

This is important because your first AI scoring system can be optimized for **spoken content**.

Do **not** initially try to support:

* Music videos
* Movies
* Gaming
* Highly edited cinematic content
* Multiple constantly changing speakers
* Automatic meme editing

That expands the problem unnecessarily.

# 2. Your Actual Requirements

## Functional requirements

The application must allow the user to:

### Input

* Paste a YouTube video URL.
* Optionally upload a local video later.
* Select desired output format:

  * 9:16
  * 16:9 clip
* Select desired clip duration:

  * 15–30 seconds
  * 30–60 seconds
  * 60–90 seconds
* Select number of clips:

  * 3
  * 5
  * 10

### AI processing

The system must:

1. Obtain/process the video locally where the user has rights or permission.
2. Extract audio.
3. Transcribe the spoken content with timestamps.
4. Break the transcript into manageable semantic chunks.
5. Analyze chunks using a local LLM.
6. Detect high-potential reel moments.
7. Score candidate clips.
8. Remove overlapping candidates.
9. Rank the best clips.
10. Generate metadata for each clip.

### For each selected clip

The system should produce:

```text
Clip title

Start timestamp
End timestamp

Duration

AI score

Why this clip was selected

Hook strength

Emotion score

Standalone context score

Curiosity score

Shareability score
```

### Video generation

The application should:

* Cut the original video.
* Convert it to 9:16.
* Generate subtitles.
* Burn subtitles into the video.
* Export MP4.
* Save all generated clips locally.

# MODULE 1 — Video Ingestion

## Responsibility

Accept a URL and prepare the video for processing.

### Input

```text
https://youtube.com/watch?v=xxxxx
```

### Process

The ingestion module should:

1. Validate the URL.
2. Create a unique project ID.
3. Retrieve metadata.
4. Download/process the source where permitted.
5. Store the source video.
6. Extract audio.

`yt-dlp` can handle the retrieval side for supported sources, while FFmpeg handles media manipulation. Use them only for content you own or have permission to process and republish.

Recommended project structure:

```text
projects/

└── project_001/
    ├── source/
    │   └── video.mp4
    │
    ├── audio/
    │   └── audio.wav
    │
    ├── transcript/
    │   └── transcript.json
    │
    ├── analysis/
    │   └── candidates.json
    │
    └── output/
        ├── clip_01.mp4
        ├── clip_02.mp4
        └── clip_03.mp4
```

# MODULE 2 — Transcription Engine

Use:

**faster-whisper**

It is a Whisper implementation built on CTranslate2 and supports CPU INT8 inference; its documentation shows lower-memory CPU configurations compared with standard Whisper. That makes it a much better fit for your 8 GB machine than blindly loading large models. ([GitHub][1])

## Recommended starting configuration

For your laptop:

```text
Model: base
Device: CPU
Compute Type: int8
Beam Size: 3
```

Do not start with `large-v3`.

That would be unnecessary.

### Output structure

```json
{
  "video_id": "project_001",
  "language": "en",
  "segments": [
    {
      "id": 1,
      "start": 0.0,
      "end": 5.2,
      "text": "Welcome everyone..."
    }
  ]
}
```

The timestamps are essential because every future component depends on them.

# MODULE 3 — Transcript Intelligence Engine

This is the brain.

## Step 1: Semantic chunking

Do not split every 5 minutes blindly.

Instead, build chunks based on:

* sentence boundaries,
* pauses,
* topic changes,
* maximum duration.

Example:

```text
VIDEO TRANSCRIPT

00:00–03:12
Introduction

03:12–07:45
Personal story

07:45–12:10
Main teaching

12:10–16:20
Emotional story

16:20–21:00
Conclusion
```

Then split large sections further if necessary.

### Target chunk size

```text
2–5 minutes
```

That is manageable for a small local model.

# 6. Clip Potential Scoring Engine

Do not allow the LLM to simply invent a random final score.

Use the LLM to evaluate dimensions.

Then calculate the final score yourself.

## Formula

```text
FINAL SCORE =
(
Hook × 0.25
+
Standalone Context × 0.25
+
Message Completeness × 0.20
+
Emotional Impact × 0.15
+
Curiosity × 0.10
+
Shareability × 0.05
)
× 10
```

Maximum:

```text
100
```

## Example

```text
Hook:                 9
Standalone Context:   10
Completeness:         9
Emotion:              8
Curiosity:            9
Shareability:         8
```

Result:

```text
Clip Potential: 91/100
```

# 7. Candidate Filtering

After analyzing all chunks, you may have:

```text
50–100 candidates
```

You cannot render all of them.

Filter them.

## Rules

### Rule 1 — Minimum duration

```text
15 seconds
```

### Rule 2 — Maximum duration

```text
90 seconds
```

### Rule 3 — Remove overlap

Example:

```text
Candidate A
12:00–12:50

Candidate B
12:30–13:20
```

These overlap.

Keep the higher-scoring candidate.

### Rule 4 — Minimum score

Example:

```text
Only retain candidates >= 65
```

### Rule 5 — Diversity

Do not return:

```text
Clip 1: 12:00
Clip 2: 12:30
Clip 3: 13:00
Clip 4: 13:30
```

That is useless.

Add a spacing rule:

```text
At least 60–120 seconds apart
```

unless explicitly requested otherwise.

# 17. Performance Rules for Your 8 GB Laptop

This matters.

## Rule 1

Only one heavy task at a time.

Bad:

```text
Whisper
+
Ollama
+
FFmpeg
+
Chrome
+
VS Code
```

Better:

```text
Whisper finishes
↓
release resources
↓
Ollama analyzes
↓
release resources
↓
FFmpeg renders
```

## Rule 2

Process one video at a time.

Do not build parallel workers.

## Rule 3

Delete temporary files.

Keep:

```text
source video
transcript
final reels
```

Delete:

```text
temporary WAV files
temporary chunks
preview files
```

## Rule 4

Start with 720p if performance is terrible.

There is no point processing 4K video on your machine.

# 21. The Biggest Risk

The hardest problem is **not downloading the video**.

Not Whisper.

Not FFmpeg.

Not React.

The hardest problem is:

> **Selecting clips that are actually worth watching.**

You need to create a testing dataset.

For example:

```text
10 long videos
```

For every video:

1. Run your system.
2. Get top 10 clips.
3. Watch all 10.
4. Score them manually.
5. Record why good/bad clips were selected.
6. Improve the scoring rules and prompts.

Create:

```text
evaluation.json
```

Example:

```json
{
  "video_id": "sermon_001",
  "clips": [
    {
      "clip_id": "001",
      "ai_score": 91,
      "human_score": 8.5,
      "result": "good"
    },
    {
      "clip_id": "002",
      "ai_score": 94,
      "human_score": 3,
      "result": "bad",
      "reason": "Requires previous context"
    }
  ]
}
```

This eventually becomes your biggest asset.
